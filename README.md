# EVALUATE

**Five clues. One diagnosis. A new challenge every day.**

EVALUATE is a pixel-art diagnostic reasoning game about neurology, neuropsychology, psychiatry and clinical psychology. Players interview fictional patients, examine them, choose investigations, weigh a differential diagnosis and commit to a diagnosis. Then they get a transparent score and a full explanation.

It runs entirely in the browser: no server, account, build step or paid service. Progress is saved in the browser's `localStorage`.

> EVALUATE is a learning game and not a substitute for professional diagnosis or treatment. All patients are fictional educational reconstructions.

---

## What's inside (Version 10)

| System | Contents |
|---|---|
| **Evaluate** (case mode) | 84 playable clinical cases, one for each playable diagnosis. Each has 8–11 interview questions, case-specific examination and test results with interpretations and plain-language explanations, alternative diagnoses with "why not" explanations, hints, references and a debrief. |
| **Pocket Clinic** | 202 encyclopedia entries: the 84 playable diagnoses plus 118 differential-diagnosis entries. Each has an overview, symptoms, causes, diagnosis, differentials, management, key features and further reading. There is also a 188-term glossary that links terms automatically. |
| **Neurdle** | A daily puzzle with five clues that resets at midnight Europe/Vienna time, with correct CET/CEST handling. It has streaks, statistics, a calendar archive, a countdown and a spoiler-free share grid. |
| **Learn** | 5 stages and 15 interactive lessons, with 30 questions and 5 guided cases. |
| **Difficulty** | Normal Mode (the default on every load) and Hard Mode. Hard Mode removes Pocket Clinic during cases, hints, plain-language explanations and evidence assistance; clinical information stays available. |

Specialty folders (20): neurodegenerative, cerebrovascular, epilepsy, movement, neuromuscular, demyelinating/inflammatory, tumours, trauma, headache, infection, sleep, cognitive, mood, anxiety/trauma, psychotic, personality, neurodevelopmental, OCD-related, dissociative/somatic, and other (metabolic, toxic, endocrine, eating disorders).

## Running it

**Locally:** open `index.html` in a browser. All data loads through ordinary `<script>` tags, so it works from `file://` too. The service worker (offline caching) only activates on `http(s)`.

**With a local server** (closest to GitHub Pages):

```bash
cd evaluate
python3 -m http.server 8000
# open http://localhost:8000
```

## Deploying to GitHub Pages

1. Create a GitHub repository and push the contents of this folder to it, so `index.html` is at the repository root.
2. In the repository, go to **Settings → Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**, select `main` and `/ (root)`, then **Save**.
4. After a minute the game is live at `https://<user>.github.io/<repository>/`.

All paths are relative, so the game works from a sub-path. No configuration file is required. The empty `.nojekyll` file stops GitHub from processing the files with Jekyll.

### Deploying updates

1. Make your changes.
2. Run the checks:
   ```bash
   node tools/validate.js      # data integrity: must print "No errors"
   node tools/build-sw.js      # refresh the offline cache list and version
   python3 tools/test.py       # browser tests and screenshots (needs Playwright)
   ```
3. Commit and push. Returning players' browsers pick up the new version automatically, because the service worker cache name is a hash of the files.

## How to add a diagnosis

### 1. Add a Pocket Clinic entry

In `js/data/entries/<folder>.js`, call `E({...})`:

```js
E({
  id: 'my-condition',            // stable, unique, kebab-case; never rename once released
  sp: 'neurodeg',                // specialty id from specialties.js
  name: 'My condition',
  alt: ['synonym', 'abbreviation'],          // searched as alternative names
  tags: ['symptom phrases people search'],   // searched as symptoms
  key: ['3–5 key features'],
  ov: 'Overview…', sx: 'Symptoms…', cause: 'Causes and mechanisms…',
  dx: 'How it is diagnosed…', mx: 'Management overview…',   // each at least 25 words
  ddx: [['other-entry-id', 'How it differs, in a sentence.']],
  read: ['referenceId']          // ids from references.js
});
```

An entry without a case counts towards the differential-entry total. An entry with a case counts as playable.

### 2. (Optional) Make it playable

In `js/data/cases/<folder>.js`, call `C({...})`. Copy an existing case as a template. Required fields:

- `id`, `dx` (the entry id), `difficulty` (1–3), `title`, `setting`
- `patient`: `{ name, age, sex, informant?, context, look: { skin 1–5, hair, hairColor, glasses?, beard?, mood } }`
- `complaint`, `duration`, `presentation`
- `interview`: 8 or more questions, each `{ c: category, q, a, s?: speaker, k?: 1 (key finding), kf?: note text }`. Categories: `onset course assoc history family meds cognition mood function sleep behaviour social`.
- `tests`: at least 3 results, keyed by test id from `tests.js`: `{ r: result, i: interpretation, p?: plain-language note, v: 'key'|'support'|'reasonable'|'low', w: why, e?: 1 (essential) }`. Tests a case does not define fall back to a normal result for standard tests, a low-value normal result for invasive tests, and a declined request for specialist tests.
- `ddx`: alternative entry ids, each with an `against` explanation.
- `hints` (2+), `summary`, `keyEvidence` (3+), `reasoning`, `mechanism`, `uncertainty`, `takeaway`
- `neurdle`: exactly 5 clues, from vague to highly discriminating.
- `refs`: reference ids.

### 3. Validate

Run `node tools/validate.js`. It checks entry completeness and section length, differential links, case structure, test ids and values, references, lesson quizzes and guided cases, the Neurdle schedule, the 14-day no-repeat rule, and the required totals. The totals (84 playable, 118 differential) are set in `js/engine/validate.js` as `REQUIRED`; update them if you deliberately expand the database.

## How daily puzzles work

- **Calendar**: the puzzle date is the calendar date in **Europe/Vienna**. `js/core/vienna-time.js` applies the EU rule explicitly. CEST (UTC+2) runs from 01:00 UTC on the last Sunday of March to 01:00 UTC on the last Sunday of October; CET (UTC+1) applies otherwise. The browser's `Intl` time zone data is used as a cross-check. The countdown targets the next Vienna midnight, so 23-hour and 25-hour days are handled.
- **Numbering**: Neurdle #1 is 1 January 2026.
- **Selection**: deterministic. The rotation comes from `js/data/neurdle-schedule.js`. For each version, the bank is shuffled once per cycle with a seeded pseudo-random generator, so every player sees the same puzzle on the same date and a refresh never changes it. At every cycle boundary, and at every version boundary, the opening puzzles are kept clear of the last 14 days, so no diagnosis repeats within two weeks.
- **Adding puzzles without breaking history**: never edit an existing schedule version. Append a new version with a future start date:
  ```js
  { from: '2027-03-01', dx: [ /* full new list, including the old ids */ ] }
  ```
  Dates before `from` keep their original puzzles. The validator warns when a playable diagnosis is missing from the latest version.
- **Play and scoring**: clue 1 is shown first. Each wrong guess or pass reveals the next clue. Solving on clue *n* scores 6 − *n* points. Wrong guesses earn nothing and lower your precision statistic, so blind guessing has no advantage over passing.
- **Persistence**: today's state, past days, archive plays, streaks, totals and accuracy live in `localStorage` under one key. Archive puzzles can be played and reviewed, but they do not count towards streaks.
- **Sharing**: the share text shows the grid (🟪 solved, 🟥 wrong guess, 🟦 pass, ⬜ unused) without the diagnosis, unless the player ticks "Include the diagnosis".

## Scoring (cases)

| Part | Points | Basis |
|---|---|---|
| Diagnostic accuracy | 40 | Correct final diagnosis |
| Clinical evidence gathered | 20 | Share of key findings uncovered (key interview answers and key tests) |
| Differential reasoning | 20 | Breadth of the board, correct diagnosis present and ranked, evidence linked for and against |
| Investigation appropriateness | 15 | −3 per low-value request (at most −12), −5 per essential test not done |
| Efficiency | 5 | Tests beyond the bedside compared with what the case needed: up to 3 extra are free, then −1 each |

Bedside examinations never count against efficiency. Hints cost 2 points each. Skipping a medically essential test costs more than any single unnecessary one, so the score never rewards cutting corners. The debrief explains every point.

## Testing

`tools/test.py` (Python Playwright) runs the game in Chromium. It checks starting and completing a case, a wrong diagnosis, interviews, investigations, adding and removing differentials, Hard Mode restrictions, Pocket Clinic search, Neurdle completion and refresh persistence, progress restore and navigation. It also checks horizontal overflow and overlapping controls, and saves screenshots at desktop (1440×900), iPad Pro 12.9" landscape (1366×1024), iPad portrait (1024×1366) and iPhone portrait (390×844).

```bash
pip install playwright && playwright install chromium   # if not already available
python3 tools/test.py ./screenshots
```

## Sources and accuracy

Clinical content was written as educational, plain-language summaries informed by established references: DSM-5-TR, ICD-11, NICE guidelines, and international consensus criteria and reviews (for example McDonald 2017, MDS Parkinson's criteria, ICHD-3, ILAE classifications, NIA-AA, McKeith 2017, Hodges & Warlow, Bárány Society PPPD criteria). Each entry and case lists its sources in **Further reading**. The registry in `js/data/references.js` contains only real publications and organisation pages. Cases are fictional reconstructions, not real patients, and the scoring is a teaching device, not a validated clinical instrument.

Fonts (Pixelify Sans for headings and Atkinson Hyperlegible for reading) load from Google Fonts. If they are unavailable, the game falls back to system fonts. After a first online visit, the service worker caches them for offline play.
